# Program the MM32 movement controller

**Pre-release guide.** Use only the qualified matched pair when published. This replaces the movement application, not just the Wi-Fi application.

## Tools and wiring

The bench workflow uses Windows, Keil µVision, Arm Compiler 6.24, the **MindMotion.MM32SPIN0x_DFP 1.0.8** device pack and a CMSIS-DAP SWD probe. Obtain the pack/toolchain separately; flash algorithms and proprietary tools are not distributed here.

With power removed, connect probe **GND → GND**, **SWDIO → DIO**, **SWCLK → CLK** at the [MM32 pad group](HARDWARE.md#programming-access). Use short leads. The board is powered separately with a verified regulated 3.3 V supply and no batteries fitted. Do not connect a probe power output in parallel. If a probe requires VTref sensing, follow its documented input requirements; do not confuse a sense input with a power output. Reset wiring is probe-specific, not required to be guessed from a generic adapter pinout.

## Candidate µVision project

The source tree includes `firmware/mm32/MM32SPIN05_Handover_RC6BB_Programmer.uvprojx`. It expects the corresponding HEX in `firmware/mm32/build/`. Build it first with the [source instructions](BUILD.md), or use the prepared matching files after release.

1. Confirm **MM32SPIN05PF**, the correct probe, SWD transport and device-pack flash algorithm in target/debug/utilities options. Do not use ULINK unless that is the probe actually connected.
2. Verify the HEX identity against [the candidate manifest](RELEASE_IDENTITY.md). Do not select an old file left in another project's build directory.
3. Power the board and use the explicit **Flash → Download** operation.
4. Confirm programming and verification succeeded. If the probe/algorithm cannot identify or verify the target, stop; do not choose a similar chip at random.
5. Close the programming session, remove power and disconnect driven programming leads before normal operation.

Automatic flash-before-debug is disabled in the supplied project. Nevertheless, **debug can reset/halt the clock and disturb timing**. Do not enter debug for a movement-smoothness test or assume a debugger connection is a passive measurement. The project's µVision Build command is not a substitute for the provided build script.

A routine upgrade should not require changing option bytes/readout protection. Do not mass-erase to remove protection or claim an original-image backup exists if the chip could not be read. Keep any verified recovery files you already own privately.

MM32 RC6BB identifies itself in RAM with signature **0x4D50529F**. End users do not need to inspect RAM to operate the clock.
